# `reference_papers/` — PDF референсных статей

## Что это

Живёт внутри `latex_documents/`, потому что первый её потребитель — текст
статьи: источник цитат, обоснований и материала для Introduction/Discussion. Но
читать её разрешено и со стороны `python_project/` — как источник фактов о
датасетах; такое обращение разделения контекстов (CLAUDE.md) не нарушает, и
только оно.

Хранит **только PDF и их провенанс**. Выводов, конспектов и рабочих заметок
здесь нет — они идут туда, куда их отправляют общие правила.

## Раскладка

Подпапки — **по назначению, а не по теме**: одна и та же статья про EEG может
лежать в любой из них, решает то, на что она отвечает.

| папка | зачем |
| --- | --- |
| `datasets_papers/` | обоснование конверсии датасетов и решений по разметке |
| `generalization_papers/` | заявка на новизну, материал для Introduction/Discussion |
| `citation_papers/` | источник конкретной цитаты в тексте: психологическая и нейрофизиологическая база, не про датасеты и не про новизну |
| `reviewer_requested_papers/` | работы, которые рецензент прямо потребовал процитировать — материал для ответа, независимо от того, войдут ли они в текст |

Имена файлов — описательные слаги без нумерации: слаг читается без похода в
`refs.bib`. Порядок строк в таблицах `SOURCE.md` значения не несёт.

## `SOURCE.md` — индекс происхождения, и только он

Индекса верхнего уровня нет: в каждой подпапке свой `SOURCE.md`, и он отвечает
ровно на один вопрос — **откуда взялся файл**: публикация, DOI, какая это версия
(опубликованная OA / postprint / preprint / платная), плюс заметка, если
издатель блокирует автоматическое скачивание.

Соответствие слага с bib-ключом не теряется: у каждой строки есть колонка
bib-ключа — конкретный ключ, если статья процитирована в рукописи, или прочерк,
если она собрана только как обоснование и в `refs.bib` не заведена.

Что из статьи **следует** — там не пишется. Для датасетов это README самого
BIDS-корня, для рукописи — её текст и рабочие `.md` в корне репозитория.

`SOURCE.md` объясняет содержимое своей же папки, поэтому под правило «рабочие
`.md` — в корень» не подпадает.

## Новый PDF

Кладётся в подпапку по назначению и **той же правкой** получает строку в её
`SOURCE.md`. Файл без строки — потерянное происхождение: по PDF не
восстанавливается ни версия, ни лицензия, ни то, почему он здесь.
