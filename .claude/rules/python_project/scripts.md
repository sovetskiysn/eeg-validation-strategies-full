# `scripts/` — Makefile как пульт, скрипт как линейный сценарий

## Что это

Правило про всё содержимое `python_project/scripts/` — существующие `run_*.py`
и любой скрипт, который появится позже. Оно описывает две вещи: **как скрипт
запускается** и **как он устроен внутри**. Архитектура стадий и границы Hydra —
в `overview.md`.

## Makefile — пульт запуска для пользователя

Пользователь не открывает `.venv` и не набирает `uv run python scripts/...`
руками: его способ запустить что-либо — `make <цель>` из `python_project/`.
Команда запуска — тоже часть исследования. Набранная в терминале, она живёт до
закрытия сессии и не воспроизводится ни другим человеком, ни тем же человеком
через месяц; записанная в Makefile — лежит в git рядом с кодом, который её
обслуживает.

**Агента это не ограничивает.** Агент свободно запускает
`uv run python scripts/... ` напрямую — для проверки изменения, отладки,
разового прогона с любыми overrides. Заводить ради этого цель не нужно:
временная проверка агента и постоянный пульт пользователя — разные вещи.

Правила:

- новый скрипт получает свою цель и строку в `.PHONY` — чтобы у пользователя
  был способ его запустить;
- в Makefile попадают **воспроизводимые прогоны**, которые пользователь будет
  повторять: стадии конвейера и осмысленные конфигурации эксперимента. Разовая
  отладочная команда туда не попадает;
- Makefile остаётся тонким: экспериментальная цель — один вызов `uv run python
  scripts/run_experiment.py +experiments=<protocol>`. Логика, циклы, ветвления и
  перечисление overrides в Makefile не переезжают;
- цель — *ярлык запуска*, а не второй слой конфигурации. Значения по умолчанию и
  контракт runner'а живут в `configs/`, научные комбинации и experiment-планы — в
  `configs/experiments/`.

### Overrides живут в цели, а не в терминале и не в `ARGS=`

Прогон, который пользователь хочет иметь под рукой, оформляется именованным
`scenario`, `decoder` или корневым experiment-пресетом в `configs/experiments/`;
Makefile выбирает только `+experiments=<preset>`. Проброса overrides снаружи
(`make sweep ARGS=...`) нет: состав
эксперимента обязан лежать в git, а не в истории терминала.

**Запрет касается overrides, составляющих эксперимент.** Аргумент, адресующий
уже произведённый выход, под него не подпадает: он не меняет, что посчитано.

### Одна цель `experiment`, выбор пресета — правкой Makefile

`configs/experiments/` — обычная Hydra config group внутри `configs/`, а не
отдельный search root: её опции выбираются `+experiments=<preset>` тем же
composition-механизмом, что и любую другую группу. Единственная цель
`experiment` запускает `uv run python scripts/run_experiment.py
+experiments=<preset>`; чтобы переключить прогон, пользователь меняет имя
пресета прямо в строке Makefile. Отдельных целей на каждый пресет или на
`scenario`/`decoder` по отдельности нет — это увеличило бы число целей без
выигрыша, раз выбор всё равно одна строка.

Корневые пресеты (`configs/experiments/scenario_decoder.yaml`,
`baseline_logistic_regression.yaml`, `ica_ablation.yaml`) сами задают
`hydra.sweeper.params`, то есть какие `scenario`/`decoder`/`validation_strategy`
входят в sweep, и `hydra.mode: MULTIRUN` — режим принадлежит пресету, потому
что без него `sweeper.params` молча не сработали бы при обычном запуске. Корень
`results/` пресет не называет: имя каталога базовый конфиг берёт из имени
самого пресета (`results_layout.md`).

`scenario_decoder.yaml` — полное декартово произведение всех `scenario` и всех
`decoder` recipes: обе группы — плоские директории без вложенных подпапок, и
sweep по каждой задаётся `+experiments/scenario: glob(*)` /
`+experiments/decoder: glob(*)`. Плоская раскладка — не случайность:
**Hydra `glob(*)` не рекурсирует по подпапкам группы**, поэтому вложенные
папки под `scenario/` (когда-то были `distinguishing/`, `sam40/`, `transfer/`
ради навигации) вынуждали бы full-sweep пресеты перечислять каждый путь
вручную — и новый scenario-файл, забытый в списке, молча выпадал бы из sweep.
Различие между датасетом и направлением scenario несёт имя файла
(`sam40_arithmetic.yaml`, `sam40_to_distinguishing.yaml`, ...), а не каталог.

Зависимые оси не передаются BasicSweeper отдельно. Пара «признаки × pipeline»
является одной decoder option; допустимый source с составом и списком его
targets — одной scenario option. Поэтому Hydra перемножает
только корректные целые рецепты и не создаёт совпадающие transfer-пары или
модели с чужим входом. Какой датасет попадает в scenario — следствие того, что
подтверждает источник; протокол (`validation_strategy`) — независимая ось,
выбираемая отдельно от scenario, и дополнительно отвергает чужой датасет.

**Метку прогона Makefile не пишет.** Каталог job'а именует Hydra по тому, что
действительно было в командной строке; читаемое имя состава собирает анализ из
сохранённого конфига. Рукописная метка ничем не проверяется и расходится с
составом — её появление в цели считать регрессом.

### Состав SAM-40 задаётся задачами

Поле `mne_bids_pipeline.task` в preparation source и каждом элементе
`preparation.targets` — источник истины для состава SAM-40. Scenario задаёт
полный список (`[relax, stroop]`, ...) и всегда включает `relax`: это
low-demand класс. Для Dataset A значение — строка `attention`.

Корневой config выбирает одну preparation-option. Non-transfer scenario
оставляет её одной стороной; transfer scenario композит те же options в
`preparation.source` и именованный mapping `preparation.targets`, после чего
переопределяет нужные Pipeline-поля. Отдельного `cfg.dataset`, а также полей
`recipe` и `overrides` нет. Validation-builder получает готовый
`preparation_config`, а `src/preparation.py` — только соответствующий
`mne_bids_pipeline`. Все ключи сверяются с аннотациями Pipeline, а YAML
list/tuple приводятся по тем же аннотациям. Runner отдельную функцию подготовки
не вызывает.

## Устройство скрипта: линейный сценарий, а не набор функций

Требование «одна функция» сформулировано для experiment runner'а, но дух общий:
скрипт в `scripts/` — не место для технической обвязки. Разрастается — значит
логика уехала не туда.

Что делать вместо `_`-хелперов, которые в такой файл просятся (`_load_dataset`,
`_build_cv`, `_extract_features`, `_save_tables`):

- разделять шаги баннером-заголовком (`overview.md`), а не `def`. Каждый такой
  хелпер вызывался бы ровно один раз, из одного места, в фиксированном
  порядке — это не переиспользование, а оглавление, за которое платят прыжками
  по файлу и протаскиванием `cfg` через сигнатуры;
- различается научный сценарий — он живёт отдельной функцией в `src/` и
  выбирается из конфига; скрипт не ветвится по имени стратегии;
- кусок действительно переиспользуемый и научный по смыслу — ему место в `src/`
  по правилам `overview.md`.

Обёртки ingestion — тонкие, без Hydra: пути и вызовы функций из плоского `src/`.
Они **несимметричны намеренно**: наличие функции в `src/` не означает, что
датасет принят в состав, и обёртка зовёт только принятое (`datasets.md`).

## Адресация уже произведённого выхода

Скрипт анализа читает дерево `results/`, поэтому его вход — не эксперимент, а
каталог:

- **job-каталог определяется файлом, а не глубиной**: наличие сохранённого
  Hydra-конфига и есть определение job'а. Одиночный прогон, один sweep и
  составной sweep обрабатываются одним кодом, как и любая будущая раскладка.
  Свой собственный выход скрипт за вход не примет;
- **каталог задаёт переменная окружения**, которую читает сам скрипт; без неё
  берётся самый свежий каталог верхнего уровня. Пробрасывать переменную в
  рецепт не нужно: make сам кладёт переменные командной строки в окружение;
- имя переменной не должно сталкиваться с уже занятыми словами — ни с
  переменной, означающей «куда писать» результаты прогона, ни с терминами Make
  и самого проекта;
- **выход всегда лежит внутри того, из чего посчитан.** Провенанс получается сам
  собой, и вопрос «по каким прогонам это?» не возникает. Вложенные каталоги
  анализируются по отдельности и друг другу не мешают;
- **падать громко нужно на прерванном прогоне**: job-каталог есть, а таблиц
  нет — значит, сравнение посчиталось бы по неполному набору. Пустой лист
  сравнений, наоборот, валиден: если job один, сравнивать не с чем.
