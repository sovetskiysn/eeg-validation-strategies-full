# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Monorepo одного научного исследования по декодированию внимания на EEG:
zero-shot перенос декодера между субъектами, сессиями, задачами, датасетами и
парадигмами. Две половины:

| Директория | Содержимое | Стек |
| --- | --- | --- |
| `latex_documents/` | текст статьи, ответ рецензентам, шаблоны и guidelines журнала | LaTeX |
| `python_project/` | код: загрузка датасетов, BIDS, препроцессинг, эксперименты, анализ | Python, `uv`, MNE / scikit-learn / braindecode |

Больше основных папок нет: всё содержательное лежит в этих двух. В корне
репозитория кроме них появляются только рабочие `.md`-артефакты и тематические
папки-группировки для них — см. «Рабочие `.md` — в корень» ниже.

Половины лежат вместе, потому что агенты нужны и для текста, и для кода, и всё
это должно версионироваться одной историей git.

`.claude/` — единственный источник контекста и для Claude Code, и для Codex
(см. `AGENTS.md`). Дублировать инструкции в других местах не нужно.

## Рамка исследования

Формулировка задачи зафиксирована во введении
`latex_documents/revision/manuscript_clean/manuscript.tex`; ей подчиняются обе
половины. Коротко — чтобы код и текст не расходились в терминах:

- **Вопрос.** Сколько дискриминативности сохраняется, когда декодер применяют к
  данным, полученным не так, как обучающие: другой участник, сессия, trial,
  задача, датасет-парадигма. Меряется zero-shot, без адаптации на target;
  направленные пары source→target читаются против target-specific baseline.
- **Зачем.** Результат — pre-adaptation benchmark: точка отсчёта, относительно
  которой будут читаться выигрыш и negative transfer методов transfer learning
  и domain adaptation. Это не соревнование за accuracy и не заявка на новую
  архитектуру.
- **Что на самом деле предсказывается.** Метка в обоих датасетах задана
  протоколом, а не измерением состояния участника: классы — это контраст
  «условие с высоким протокольным task demand» против «отдых или отключение от
  задачи», а не уровень внимания. Так это и называется — в тексте, в именах классов и в
  комментариях кода. Из наших данных не следует утверждение «инвариантного
  маркера внимания нет»; следует утверждение про данные с protocol-defined
  метками.
- **Что является фактором дизайна.** Протокол валидации и декодер — две оси, а
  не фон: шесть протоколов (baseline, cross-subject, cross-session, cross-trial,
  cross-task, cross-dataset) и шесть декодеров от логистической регрессии до
  EEGPT. Различие между протоколами, устойчивое по всем шести декодерам, —
  свойство данных и протокола, а не свойство конкретного декодера.
- **Что ограничивает состав.** Протокол применяется только к тому датасету, чей
  релиз его поддерживает: cross-session — только к записанному по повторным дням
  Dataset A, cross-trial и cross-task — только к SAM-40, где у одного участника
  есть повторы протокола и несколько задач. Сливать их под общим именем нельзя.

Имена в статье и в коде: **Dataset A** = `distinguishing` (mental attention
state, симулятор поезда), **Dataset B** = `sam40` (SAM-40, нейрокогнитивные
тесты).

## Разделение контекстов — обязательное правило

**По умолчанию контексты `latex_documents/` и `python_project/` разделены и не
смешиваются.** Случай, когда нужны оба одновременно, редкий; пользователь
скажет об этом явно.

Перед работой определи сторону по путям в задаче и подгружай только её
контекст. Здесь только маршрутизация — детали живут в самих правилах:

- `latex_documents/**` → `.claude/rules/latex_documents/overview.md`.
  Скиллы: `plos-one-review`, `scientific-critical-thinking`;
- `python_project/**` → `.claude/rules/python_project/`: `overview.md` (стиль
  кода, запуск, раскладка, границы стадий), `datasets.md` (каталог
  `datasets/`: провенанс источников, стандарт метаданных BIDS, отбор записей,
  кэш Stage 1), `scripts.md` (Makefile и устройство `scripts/`),
  `notebooks.md`. Скиллы: `ClaudeEEG`, `bids`, `scikit-learn`,
  `statistical-analysis`;
- `latex_documents/reference_papers/**` (PDF референсных статей) →
  `.claude/rules/latex_documents/reference_papers/overview.md`. Папка лежит
  внутри `latex_documents/`, но читать её можно и со стороны
  `python_project/` — как источник фактов о датасетах; это **единственное**
  исключение из разделения контекстов;
- обе стороны сразу — только по явной просьбе пользователя.

Не читай файлы противоположной половины «на всякий случай», не переноси её
терминологию и решения.

Дерево `.claude/rules/` зеркалит корень репозитория, поэтому маршрутизация
читается по имени папки, а подключение — по `paths:` во frontmatter.

## Рабочие `.md` — в корень, на разбор пользователю

Половины хранят **предмет** работы: `.tex` и материалы статьи, `.py` и данные.
Всё, что пишется **про** работу — планы, разборы, сравнения вариантов, отчёты
агентов, аудиты, промежуточные выводы, мокапы — кладётся **в корень
репозитория** отдельным файлом (`.md`, реже `.html` для мокапа). Имя —
заглавными с подчёркиваниями по содержимому.

Корень для таких файлов — не место жительства, а **очередь на разбор**:

1. создаёшь файл в корне и явно называешь его в ответе — пользователь должен
   увидеть артефакт сразу, не выискивая его;
2. дальше решает только пользователь: файл переезжает в `.claude/` как
   постоянный контекст, его содержание уходит в текст статьи или в код, либо
   он удаляется как временный;
3. без явного подтверждения — не переносить в `.claude/` и не удалять молча.

Прятать такой файл в подпапки половин, в `docs/`, сразу в `.claude/` или во
временные каталоги нельзя: спрятанное пользователь проглядит, и мусор осядет
навсегда. Отсюда следствие: **каталогов `docs/` под артефакты работы внутри
половин не заводим.**

**Группирующие папки в корне.** Когда по одной теме таких файлов набирается
много, пользователь сводит их папкой в корне (`thinking_about_<...>_section/`,
`task_<...>/` или как назовёт по случаю). Это та же очередь, только
сгруппированная. Новый файл по теме существующей папки кладётся в неё; всё
прочее — отдельным файлом в корень. Новую группирующую папку заводит
пользователь, не агент.

Правило касается только артефактов работы. Под него **не** подпадают и
остаются на месте:

- внешние материалы, записанные в `.md` для удобства (письма редактора, тексты
  полей формы подачи);
- файлы, объясняющие содержимое своей же папки (`SOURCE.md`, `README.md`);
- постоянные карты и индексы, которые ведутся от версии к версии.

## Общие конвенции

### Единые конфиги в корне

Инструментальные файлы (`.gitignore` и т.п.) держим в одном экземпляре в корне,
а не по одному на компонент. Секции для половин разделяются
комментариями-заголовками внутри одного файла, пути префиксуются
(`python_project/**`, `latex_documents/**`). Прежде чем заводить новый конфиг
внутри половины, проверить, нельзя ли расширить корневой файл.

### Правила из плагинов не копировать

В `.claude/rules/` лежит только написанное под этот репозиторий. Правила
плагинов копированию не подлежат: они описывают чужой стек и не являются
источником архитектурных решений проекта. Каждая зависимость и каждая
абстракция в `src/` принимается отдельным решением по критерию из
`rules/python_project/overview.md`, а не потому, что так делает плагин.
Плагины остаются включёнными в `settings.json` — их скиллы и агенты работают и
без копий. Нужна конкретная строка из плагина — выписать её в существующее
правило.

### Git-коммиты

Никогда не добавлять `Co-Authored-By: Claude ...` в сообщения коммитов —
пользователь не хочет публично отмечать AI-соавторство.
