# Актуальные причины низких метрик

Этот файл заменяет разрозненные диагностики метрик и фиксирует только то, что
остаётся проблемой в текущем дереве. Он относится к рецепту подготовки с
MNE-BIDS-Pipeline и ICLabel, а не к историческим кэшам с EOG-proxy.

## Что уже не является проблемой

- `cross_trial` удалён из конфигов, сценариев и validation-кода намеренно; он
  не является частью текущего дизайна.
- ICA больше не использует F3/F4/F7/F8 как EOG-proxy. Вместо этого включён
  ICLabel; на v12 он поднял SAM-40 в проверке логрега с 0.572 до 0.602 для
  leave-recording-out и с 0.559 до 0.589 для leave-subject-out.
- Ресэмплинг до внутреннего `ValidSplit` удалён. Все декодеры получают
  fold-specific class weights; точные копии окон больше не могут попасть в
  inner-train и inner-valid одновременно.
- Проверка качества каналов не объясняет низкие метрики: в обследованных
  записях было не более одного автоматически помеченного канала.

## Открытые проблемы

| Приоритет | Проблема | Почему это важно | Следующее решение / проверка |
| --- | --- | --- | --- |
| P0 | Нет честного `within_recording` ориентира | Текущий `baseline` — это уже leave-recording-out. Без temporally blocked контроля непонятно, сколько сигнала доступно при данных той же записи и почему числа ниже работ с random segment split. | Добавить отдельный time-blocked `within_recording` с зазором не меньше одного окна. Публиковать его только как calibration/upper bound, а не как zero-shot baseline. |
| P0 | ICLabel заменил опасное правило, но ICA ещё не верифицирована как окончательное решение | ICLabel исключает 11.7% компонент SAM-40 против 0.6% Dataset A. Кроме того, он применяется к данным с Nyquist 64 Hz и 12 каналами, тогда как его штатная область шире. Улучшение v12 обнадёживает, но не доказывает, что исключаемые компоненты не несут task-correlated сигнал. | На фиксированных конфигурациях сравнить ICLabel и `no_ica` для SAM-40 (cross-recording, cross-subject) и Dataset A как контроль. Не подбирать порог ICLabel по test score. Зафиксировать правило и limitation в Methods. |
| P0 | Inner validation нейросетей не group-aware | `ValidSplit(0.2, stratified=True)` всё ещё случайно делит окна одной recording unit между inner-train и inner-valid. Внешний test чист, но early stopping выбирает эпоху по оптимистичному validation loss. | Заменить inner split на разбиение по `recording_unit`; особенно проверить маленькие train-наборы. |
| P1 | Ось сложности протоколов смешана с размером train | `cross_session` обучается только на других сессиях того же субъекта, поэтому получает намного меньше train units, чем cross-recording и cross-subject. Просадку нельзя читать только как domain shift. | Добавить learning curves или контроль с уравненным числом train recording units; рядом с каждой метрикой показывать train windows, units и subjects. |
| P1 | Не принято решение о нормализации внутри записи | Z-нормализация по target recording ранее давала заметный прирост, но использует статистику неразмеченной target-записи. Это unsupervised target adaptation и не соответствует текущему строгому определению zero-shot, если не назвать её явно. | Либо оставить только train-fold scaling в основной таблице, либо ввести recording-wise normalisation как отдельный, одинаково применяемый adaptation protocol. Не смешивать эти результаты. |
| P1 | ICA обучается на полной recording unit до внешнего split | Метки не используются, но при time-blocked within-recording это preprocessing по будущей test-части. Это влияет на интерпретацию calibration-контроля. | Для strict calibration либо отключить ICA, либо fit ICA только на train-части; в остальных протоколах явно описать recording-level preprocessing. |
| P2 | SAM-40 может быть неверно задан на уровне 5-секундного окна | Даже в абляциях без старого EOG-proxy SAM-40 оставался около 0.62 на оконной классификации; усреднение пяти окон записи не улучшало результат. Общие 12 каналов также стоили SAM-40 примерно 0.04. | Отдельно проверить prediction на уровне полного 25-секундного recording и абляцию 12 общих против доступных 32 каналов, не меняя split и модель. |
| P2 | Главная таблица пулит предсказания разных фолдов, включая ROC-AUC | Вероятности разных fold-models могут быть по-разному калиброваны; это особенно существенно для leave-one-subject-out. | Для основных метрик считать mean/dispersion по folds (и subject-level summary там, где применимо); pooled ROC-AUC оставить только дополнительной величиной. |
| P3 | `rest_epochs_overlap: 0.5` означает 0.5 секунды, а не 50% окна | При окне 5 с это 10% overlap. Это не leakage при recording-disjoint split, но может расходиться с описанием и влияет на число окон. | Сверить текст статьи и, если нужен иной шаг, изменить параметр осознанно с инвалидацией производного артефакта. |

## Минимальный порядок работ

1. Провести ICLabel vs `no_ica` абляцию и зафиксировать окончательный ICA
   рецепт до полного sweep.
2. Сделать group-aware inner validation нейросетей.
3. Добавить `within_recording` calibration и переименовать текущий `baseline`
   в within-dataset cross-recording в таблицах и тексте.
4. Добавить контроль размера train; после этого решить, нужен ли отдельный
   протокол с target-wise normalisation.
5. Проверить единицу анализа и число каналов для SAM-40, затем пересчитать
   итоговые table/figure artifacts только на одном зафиксированном рецепте.

## Правило интерпретации

Высокие результаты случайного segment split не являются целью основного
бенчмарка: соседние сегменты одной физической записи разделяют дрейф, импеданс
и preprocessing. Основной результат — zero-shot transfer без target adaptation
по меткам; любые calibration или unsupervised-adaptation контроли должны быть
отмечены отдельно.
