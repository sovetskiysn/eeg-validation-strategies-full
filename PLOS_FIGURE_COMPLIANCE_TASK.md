# ТЗ: приведение фигур статьи к требованиям PLOS ONE

## Контекст

Статья `PONE-D-26-28965` вернулась из PLOS ONE на ревизию. Journal Requirement 1
требует привести рукопись в соответствие со стилевыми требованиями журнала,
включая требования к фигурам (<https://journals.plos.org/plosone/s/figures>).

Текущее состояние: три фигуры рукописи генерируются шириной 11–13 дюймов при
максимуме журнала 7.5 дюйма. Файлы `Fig1–Fig3.tif` в комплекте подачи
нарушают габариты почти вдвое и будут отбиты автоматической проверкой
Editorial Manager / NAAS ещё на загрузке.

Причина: фигуры верстались под экран, а не под печатный формат. Кегли в
`analysis.py` заданы абсолютными числами при холсте 12–18 дюймов. Ужать файл
постфактум нельзя — ресемплинг масштабирует пиксели вместе с текстом, и кегли
падают до 4.8–8 pt, нарушая требование «8–12 pt». Единственный рабочий путь —
рисовать холст сразу в печатном размере.

В предыдущей сессии решение было найдено и проверено, но **в рабочий код не
внесено**. Результат лежит артефактом в `cvg/` (см. раздел «Готовый артефакт»).
Задача этого ТЗ — довести решение до рабочего кода, закрыть оставшиеся
нарушения и синхронизировать текст рукописи и ответа рецензентам.

## Часть 1. Требования к конечному результату

Ниже описано состояние, которое должно быть достигнуто. Это критерии приёмки,
а не инструкции.

### 1.1. Требования PLOS ONE к фигурам

Каждый из трёх файлов `Fig1.tif`, `Fig2.tif`, `Fig3.tif` в комплекте подачи
обязан удовлетворять **всем** пунктам одновременно:

| Параметр | Требование |
| --- | --- |
| Ширина | 2.63–7.5 in (789–2250 px при 300 dpi) |
| Высота | ≤ 8.75 in (≤ 2625 px при 300 dpi) |
| Разрешение | 300–600 dpi |
| Формат | TIFF, LZW-компрессия |
| Цветовая модель | RGB 8 бит/канал или grayscale |
| Слои | flattened, без слоёв, без альфа-канала |
| Страниц в файле | одна |
| Размер файла | ≤ 10 MB |
| **Весь текст внутри фигуры** | **8–12 pt, шрифт Arial, Times или Symbol** |
| Имена файлов | `Fig1.tif`, `Fig2.tif`, `Fig3.tif` — по порядку первого упоминания в тексте |
| Содержимое файла | без номера фигуры, заголовка и имён авторов внутри картинки |
| Поля | обрезаны лишние белые поля, оставлена рамка ~2 pt |

Ширина и разрешение — **независимые** требования, выполнить одно за счёт
другого нельзя.

### 1.2. Требования к подписям и ссылкам

- Подписи фигур находятся в тексте рукописи, сразу после абзаца первого
  упоминания. Внутрь файлов фигур подписи не входят.
- Метка подписи — `Fig N.` (не `Figure N.`).
- Заголовок подписи — не более 15 слов.
- **Ссылки в тексте — в формате `Fig 1`, `Fig 2A`** (не `Figure 1`).
- Нумерация по возрастанию, по первому упоминанию.

### 1.3. Требования к содержанию фигур

**Содержание не сокращается.** Ни одна колонка, строка, панель, серия или
элемент легенды не может быть удалён ради габаритов. В частности, матрица
переноса обязана сохранить 11 колонок source–target, 25 строк
(5 источников × 5 декодеров) и оба summary-столбца.

### 1.4. Требования к воспроизводимости

- Фигуры порождаются из `python_project/src/analysis.py` штатным прогоном.
  Никаких ручных правок готовых PNG/TIFF, никаких патч-скриптов поверх
  исходника.
- Повторный прогон из того же входного каталога даёт тот же результат.
- Нарушение габаритов при сборке комплекта подачи **роняет сборку**, а не
  печатает предупреждение, которое можно пропустить.

### 1.5. Требования к согласованности документов

- Текст ответа рецензентам описывает фактическое состояние фигур. Утверждений,
  противоречащих реальности, и незакрытых `TODO` в нём не остаётся.

### E1. Кегль ниже минимума в Fig1 (нарушение требования)

**Фигура:** `transfer_matrix` → `Fig1.tif`.
**Что:** заголовки двух правых summary-колонок — `Baseline vs cross-task mean

**Важно:** с заголовками самой матрицы всё в порядке — вертикальные `Stroop`,
`Arithmetic`, `Mirror`, `Full B`, `Full A` идут 8 pt, это норма. Числа в

**Подводный камень:** кегль был снижен до 7.5 pt именно потому, что при 8 pt
эти заголовки налезали друг на друга. Замена `7.5` → `8` в одну строку вернёт
наложение. Потребуется вместе с кеглем расширить колонки (`summary_left`,
`summary_width`) или переставить переносы строк в подписях.

### E2. Шрифт не соответствует требованию (нарушение, все три фигуры)

**Что:** все фигуры рисуются шрифтом **DejaVu Sans** (дефолт matplotlib).
PLOS требует Arial, Times или Symbol. В `analysis.py` нет ни `rcParams`, ни
указания семейства.

**Ограничение окружения:** Arial в системе **не установлен**. Доступен
**Liberation Sans** — метрически совместимый с Arial клон. Проверено, что он
содержит нужные глифы: `→` (U+2192), `–` (U+2013), `—` (U+2014); тофу-квадратов
не появится.

**Смягчающее обстоятельство:** текст растрируется в PNG→TIFF, вопроса о
встраивании шрифта не возникает.

**Критично для порядка работ:** Liberation Sans **уже** DejaVu Sans по
метрикам. Смена семейства сдвинет вёрстку всех трёх фигур, а сохранение идёт с
`bbox_inches="tight"` — итоговые пиксельные размеры изменятся. Поэтому шрифт
меняется **до** подгонки E1, а габариты после этого перемеряются заново.
Побочный эффект скорее в плюс: более узкий шрифт может сам развести
summary-заголовки и упростить E1.

## Часть 5. Проверка

### 5.1. Габариты и технические параметры TIFF

Основная автоматическая проверка. Прогнать по
`latex_documents/revision/manuscript_clean_plos/figures/Fig*.tif`:

```python
from PIL import Image
import glob, os

for path in sorted(glob.glob("figures/Fig*.tif")):
    image = Image.open(path)
    width, height = image.size
    dpi = float(image.info["dpi"][0])
    checks = {
        "width_px":    789 <= width <= 2250,
        "height_px":   height <= 2625,
        "dpi":         300 <= dpi <= 600,
        "mode":        image.mode in {"RGB", "L"},
        "compression": image.info.get("compression") == "tiff_lzw",
        "single_page": getattr(image, "n_frames", 1) == 1,
        "size_mb":     os.path.getsize(path) <= 10 * 1024**2,
    }
    status = "OK " if all(checks.values()) else "FAIL"
    failed = [k for k, v in checks.items() if not v]
    print(status, os.path.basename(path),
          f"{width}x{height} = {width/dpi:.2f}x{height/dpi:.2f} in", failed)
```

## Часть 6. Замечания

- **`bbox_inches="tight"` расширяет файл под вылезающее содержимое.** Легенда,
  не помещающаяся в холст, увеличивает итоговую ширину, а не обрезается.
  Именно так в тупике №2 фигура `baseline_vs_cross_subject` при уменьшении
  `figsize` выросла до 15.75 in. Следствие: **итоговую ширину нельзя вычислить
  заранее**, её надо мерить на сохранённом файле после каждой правки.
- `scenario_accuracy_by_decoder` сохраняется **без** `tight` (см. комментарий
  в `figure_specs`), поэтому её нижнее поле обязано вместить подпись оси само —
  через `bottom` в `subplots_adjust`.
- **Ничего не удалять в `cvg/` по своей инициативе.** Каталог `plos_try1/`
  помечен в документе как кандидат на удаление, но это решение пользователя.
